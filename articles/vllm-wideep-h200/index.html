CORE THESIS

Wide-EP 的价值来自更大的共享显存与有效 batch，但它只有在 A2A、负载偏斜和通信暴露都被控制后才会兑现。

它是 vLLM 视角下最紧凑的 Wide-EP 设计说明，串起了 MLA KV 复制、DP worker 调度、专家路由、双 batch 重叠和 P/D 分离。

01
ARGUMENT 01

为什么 Attention DP、MoE EP

Attention 按请求做数据并行，每个 worker 保有独立调度器和 KV，避免 MLA latent projection 在 TP ranks 间重复。

专家层共享一个跨 DP workers 的 EP group，token 根据路由结果进入对应专家。

阅读注解

同一 rank 在 Attention 层表现为 DP worker，在 MoE 层又是 EP member；“并行组语义随 layer type 改变”是理解实现的关键。

画拓扑时应区分 Attention group 与 Expert group。

02
ARGUMENT 02

DBO 隐藏 A2A 等待

高 EP degree 下，dispatch/combine collective 的等待会让 GPU 出现明显空洞。

Dual-batch Overlap 用两个 microbatches 交替推进，让一个 batch 的通信与另一个 batch 的计算重叠。

阅读注解

DBO 不是免费并发：阈值过低会增加线程、graph 与调度开销；必须在通信占比较高的 decode shape 上触发。

优化目标是缩短 exposed communication，而不只是缩短 collective 本身。

03
ARGUMENT 03

EPLB 与 P/D 分离

在线流量会产生 expert hot spots，EPLB 依据滑动窗口重映射 logical experts，并搬移权重。

Prefill 大批量与 Decode 小批量需要不同 DeepEP 模式，P/D 分离让两侧分别选择吞吐或时延路径。

阅读注解

负载均衡、冗余专家和 PD 都在减少 tail amplification：任意一个慢 rank 都可能延长整个 EP step。

Wide-EP 的性能指标必须包含 rank-level tail，而非只有平均 TPS。

01机制

为什么 Wide-EP 能扩大有效 KV cache？

查看提示

Attention 权重是否必须像专家一样分片？

参考推导

DP Attention 让每个 rank 处理不同请求并保存自己的 KV；专家权重则跨 ranks 分布。相比对整个模型做大 TP，它避免 MLA KV 在 TP ranks 上复制，把更多显存留给不同请求的 KV。

02推导

DBO 在什么情况下可能无收益甚至退化？

查看提示

考虑小 EP、低通信占比和 microbatch 大小。

参考推导

当 A2A 很短、batch 太小、计算本身占主导或 microbatch 切分破坏 GEMM 效率时，重叠空间不足，线程切换、同步与 graph 管理开销会超过被隐藏的通信。

03设计

如何判断应该增加 redundant experts，还是缩小 EP size？

查看提示

一个解决 skew，一个减少通信域。

参考推导

同时 sweep EP degree 与冗余数，观察 KV capacity、expert token 分布、A2A 时间和尾延迟。若主要问题是少数热点 rank，冗余更直接；若跨节点通信普遍占主导且 batch 不足，缩小 EP 更有效。
