CORE THESIS

服务 hybrid 2.8T MoE 的难点不是让每个功能单独可用，而是保证 cache、并行、speculation 与 P/D 在同一状态语义下组合。

与 LMSYS K3 文章并读价值最大：同一模型、不同实现选择，可以区分模型强制约束与框架自身设计偏好。

ARGUMENT 01

Hybrid Prefix Cache 的新语义

KDA 固定 recurrent state 与 MLA token-level KV 必须在同一逻辑 prefix 上对齐。

physical state block 可以比 prefix-match granularity 更大，从而既避免每小块保存完整 recurrent state，又保留 partial hit。

阅读注解

缓存命中不再等价于“找到连续 KV blocks”；它还必须证明 recurrent state 恰好对应命中边界。

Hybrid cache 需要同时定义匹配粒度与状态物化粒度。

02
ARGUMENT 02

Sequence Parallel TEP Prefill

Attention 走 TP、MoE 走 EP，TEP 可保留完整 experts 并改善 expert GEMM。

Sequence parallel 把 token ownership 分给 ranks，减少 attention residual 的重复物化，并在必要位置 all-gather。

阅读注解

TEP 的风险是每层多个 collective。Sequence parallel 的目标不是减少模型计算，而是减少 rank 间重复数据和同步。

分析混合并行要精确到每层 collective 的位置与 tensor shape。

03
ARGUMENT 03

DEP Decode 与 DSpark 的兼容

高吞吐路径让 Attention 数据并行、experts 跨 ranks 分片，并使用适合拓扑的 MoE/A2A backend。

DSpark draft 被设计成与目标 MLA cache layout 相容，避免 speculative path 破坏 PD 与高级 KV 管理。

阅读注解

speculative decoding 常被当作独立插件，但在 hybrid model 上 draft/verify/rollback 都会触碰多种状态；布局兼容比算法接受率更基础。

所有加速路径都必须复用同一套状态提交协议。

01机制

为什么 hybrid prefix cache 要区分 match granularity 与 state block size？

查看提示

小粒度命中与大 recurrent state 的存储成本冲突。

参考推导

细粒度 match 能提高命中率，但若每个小块都快照完整 KDA state，存储成本会爆炸；分离后可在小 token 粒度查找，只在更粗的合法边界保存/恢复 recurrent state。

02推导

TEP 相比纯 TP 的收益与新增代价分别是什么？

查看提示

比较 experts 是否完整以及每层 collective 数量。

参考推导

TEP 把完整 experts 放在不同 ranks，改善 MoE GEMM shape 并减少专家内部 TP；代价是 Attention TP 与 Expert EP 使用不同通信语义，可能在每层引入额外 all-reduce/all-gather 和 token dispatch。

03设计

如何比较 LMSYS 的 PP Prefill 与 vLLM 的 TEP Prefill？

查看提示

控制模型、硬件与 workload，并拆解 compute/communication。

参考推导

固定 K3 checkpoint、硬件域、precision、chunk 和请求分布，对 PP8 与 TEP8 sweep concurrency/ISL；记录 TTFT、input TPS、GEMM efficiency、collective/P2P exposed time、显存和启动复杂度，按 SLO 取 Pareto，而非只比较峰值。
