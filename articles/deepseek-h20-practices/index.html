CORE THESIS

EP degree 的最优点由 batch、拓扑和 SLA 共同决定；更多 GPUs 只有在本地通信比例与计算利用率保持良好时才等于更高效率。

文章给出了非常具体的部署和 batch sweep，并把微观性能结论落到 Base/Pro/Max 三档线上服务。

ARGUMENT 01

Prefill 与 Decode 的独立配置

Prefill 使用单节点 TP8，强调计算吞吐与避免跨节点 collective。

Decode 采用两节点 Attention-DP16 + MoE-EP16，利用更大 KV capacity 与专家分片。

阅读注解

这体现一个实用原则：把高频 collective 限制在最快互联域，把跨节点通信留给更能从聚合 batch 获益的部分。

硬件拓扑应直接映射到通信组边界。

02
ARGUMENT 02

EP16 为什么能超过 EP32

EP32 让更多 MoE traffic 离开 NVLink 域并走跨节点网络。

batch 增大后，EP16 的 GEMM 足够饱满，而 EP32 仍支付更高 A2A 与同步成本。

阅读注解

EP 扩展有一个“容量/批量收益”与“通信域扩张”交叉点。它必须用目标 batch sweep，而不能由 GPU 数直觉决定。

报告 EP 性能时必须附带 batch 与拓扑。

03
ARGUMENT 03

SLA Tier 对应不同运行点

Base、Pro、Max 分别使用不同 batch 与 MTP 参数，以换取吞吐或更低 TPOT。

相同 engine topology 可以通过运行时 knobs 覆盖多档服务，但容量要分别核算。

阅读注解

产品层的 tier 最终必须落成可验证的 batch/queue/speculation policy，而不只是不同的价格标签。

每个 SLA tier 都应有独立 Pareto 曲线。

01机制

EP32 比 EP16 多出的主要代价为什么不是权重显存？

查看提示

专家权重更分散后，token 要去哪？

参考推导

更大 EP group 使 token dispatch/combine 覆盖更多 ranks 和节点，降低本地 NVLink 命中比例，增加网络 A2A、同步长尾和更小的 per-rank token/GEMM。

02推导

为什么严格 TPOT tier 往往选择更小 batch？

查看提示

单 step 时间与排队/组批等待如何变化？

参考推导

更小 batch 减少一次 step 的工作量和组批等待，使单 token 返回更快、更稳定；代价是 GEMM/带宽利用率下降，因此吞吐和 token 成本通常更差。

03设计

如果 IB 带宽下降 30%，应先调整哪些 knobs？

查看提示

减少跨节点流量或隐藏其延迟。

参考推导

先评估缩小 EP、重排 rank 以提高 NVLink locality、降低 batch 或启用更有效 overlap；同时调 P:D 配比和 admission control。选择应以 A2A exposed time 与 SLO goodput 的新 sweep 为依据。
