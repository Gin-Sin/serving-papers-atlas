CORE THESIS

P/D 分离的真正抽象不应是“搬 KV”，而应是按模型状态类型描述 ownership、布局、粒度和可传输区域。

它直接进入 connector 和 block manager 的数据结构层，解释 hybrid model 为什么让统一 KV block 假设失效，也是理解后续 Qwen3.5、Kimi K3 支持的技术底座。

阅读官方原文
01
ARGUMENT 01

一种 KV 格式的抽象失效

FA KV 随 token 增长并分页；SSM state 通常按 request 固定，且包含 recurrent 与 convolution state。

原有 connector 假设统一 block 大小和布局，无法正确描述两类状态。

阅读注解

这类 bug 往往不是 kernel 错，而是“逻辑 block”与“物理内存区域”被错误等同。

状态传输协议必须把语义粒度和物理布局分开。

02
ARGUMENT 02

Dual Descriptors 与 Block Bridging

两套 descriptor 以不同 offset/size 索引同一物理 HMA buffer，分别服务 FA 和 SSM。

logical-to-physical mapping 处理 block manager 粒度与 kernel 所需物理 block 的不一致。

阅读注解

共享底层 tensor 避免额外 buffer 和 permutation，但也要求 metadata handshake 精确携带每种 view 的布局。

零拷贝设计通常把复杂度转移到 metadata 正确性。

03
ARGUMENT 03

异构 TP 的三段 Conv Transfer

P 与 D 的 TP degree 不同时，conv state 在 sender/receiver 上的分片形状不同。

将连续区域分解成多个 descriptors，可在不让 sender 先重排的情况下完成传输。

阅读注解

异构并行度是 PD 最重要却最容易忽略的能力；否则两侧虽然分离，仍被迫使用同一拓扑。

验证需要覆盖 TP-P ≠ TP-D，而不只是同构 happy path。

01机制

为什么 FA KV 与 SSM state 不能共享一种 block descriptor？

查看提示

比较增长维度、生命周期和物理布局。

参考推导

FA KV 以 token block 增长，SSM recurrent/conv state 更接近 per-request 固定状态，两者 block 大小、offset、有效区域和 TP 分片方式都不同；强行统一会造成错位、冗余传输或错误状态。

02推导

零额外 buffer 为什么可能提升性能，却提高正确性风险？

查看提示

数据移动少了，metadata 责任变大。

参考推导

复用同一物理 tensor 可消除 staging copy 和 permutation，但所有 offset、长度、block ownership 与 tail region 都必须由 descriptors 正确表达；任何映射错误都可能读取陈旧或属于其他请求的数据。

03设计

为 hybrid PD connector 设计最关键的五类测试。

查看提示

覆盖模型、布局、并行度、边界和生命周期。

参考推导

至少覆盖纯 FA 回归、混合层布局、P/D 同构与异构 TP、partial/final block、取消与 block reuse；再加入跨节点传输失败、重复 handshake 和数值一致性检查。
