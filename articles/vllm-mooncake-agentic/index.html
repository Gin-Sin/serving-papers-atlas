Mooncake：Agent 流量需要集群级 KV Pool

从长会话、跨实例 miss 出发，构建带全局元数据、GPUDirect RDMA 与 MultiConnector 的分布式 KV Cache。

vLLM workers + Mooncake clients → RDMA DRAM/SSD pool · cluster master metadata · PD MultiConnector

CORE THESIS

Agent 请求的真实工作集属于整个会话而不是某个 replica；当调度会迁移请求时，KV Cache 必须从本地优化升级为可跨实例发现和读取的集群状态。

文章基于真实 coding-agent trace 解释为何本地 offload 和 sticky routing 不足，并展示同一 KVConnector 抽象如何同时支撑分布式缓存与 P/D 分离。

ARGUMENT 01

Agent Workload 为什么改写成本模型

多轮 agent 每次只增加少量工具结果和输出，但会反复携带不断增长的完整历史。

文章分析的 trace 具有极高 prefix 重复率和输入输出比；本地容量有限，跨 replica 调度又会制造 cold miss。

阅读注解

普通聊天常按单次 input/output 长度估成本；agent 更应按 session 的增量 token、轮间间隔和 prefix residency 建模。完整 prompt 很长，不代表每轮必须重新执行同样多的 Prefill。

Agent serving 的基本调度单位应从 request 扩展到 session state。

02
ARGUMENT 02

全局元数据与分布式数据面

Mooncake master 管理 block hash、位置、client health 与失效清理，scheduler 先查询匹配前缀。

每个 GPU worker 内嵌 client，管理本地 DRAM/SSD 并通过 RDMA 与其他节点交换 KV blocks。

阅读注解

元数据路径回答“块在哪里且是否有效”，数据路径回答“怎样把块搬到目标 HBM”。两者分开扩展后，也必须处理 stale metadata、节点死亡和并发写入。

分布式缓存首先是 metadata consistency 系统，其次才是高速 copy 系统。

03
ARGUMENT 03

为什么强调 SM-free 与 Fully Async

注册 GPU KV 内存后，GPUDirect RDMA 可在 HBM 与远端内存之间直接搬运，无需 CPU staging，也不占用 SM copy kernel。

RDMA descriptor 准备仍有 CPU 成本，因此所有 I/O 下发放到独立后台线程，避免延迟主线程的 GPU kernel launch。

阅读注解

“RDMA 是异步的”只描述设备操作，不代表调用路径没有 CPU 工作。端到端异步必须把描述符构建、提交、完成通知和错误处理一起移出关键控制路径。

检查异步设计时，沿 CPU launch path 追踪所有可能阻塞点。

04
ARGUMENT 04

MultiConnector 如何组合 PD 与历史缓存

Prefill 侧既通过 PD connector 把本次 KV 交给 Decode，也通过 store connector 写入集群缓存；历史命中则先从 pool 恢复。

Decode 产生的新 KV 可写回 pool；当前设计仍由 Prefill 读取历史缓存后转交 Decode，未来可扩展为多路径并行加载。

阅读注解

两个 connector 解决不同生命周期：PD handoff 服务当前请求，distributed store 服务未来轮次。组合后要避免重复搬运，并明确谁负责 lookup、ownership 与完成条件。

同一份 KV 可以同时位于请求数据流与长期缓存数据流。

01机制

有了 sticky routing，为什么仍需要分布式 KV pool？

查看提示

考虑容量、故障、扩缩容和负载均衡。

参考推导

sticky routing 只能提高命中概率，无法保证原实例仍存活、仍有容量或没有排队；扩缩容、故障转移和热点均衡都会迁移会话。分布式 pool 让 KV 与单个 replica 解耦，为跨实例命中和更大的聚合容量提供后备路径。

02推导

为什么 GPUDirect RDMA 不占 SM 仍可能影响模型执行？

查看提示

共享的不只有 SM。

参考推导

RDMA 会竞争 HBM、PCIe/NVLink、NIC 和内存控制器带宽，也会产生 CPU descriptor 与完成处理；大量小 block 还可能放大元数据和队列开销。因此 SM-free 只消除一种干扰，仍需测 attention/MLP 与传输并发时的带宽争用。

03设计

如何联合设计 cache-aware routing 与 distributed lookup？

查看提示

优先本地性，但避免热点和无限等待。

参考推导

router 用 session/block locality、worker queue、KV headroom 和健康度打分：优先选择已有本地前缀且未拥塞的 worker；若本地队列代价超过远端 load 或重算代价则迁移。请求携带 cache key/epoch，scheduler 查询全局位置并设置 I/O deadline，同时保留无缓存 fallback。
