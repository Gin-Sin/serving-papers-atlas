CORE THESIS

Hybrid Attention 的性能上限同时取决于新算子的 kernel、异构状态的传输效率，以及 scheduler 对传输完成事件的正确排序。

它把底层 hybrid-state 支持与端到端 Pareto benchmark 连起来，能看到一次模型支持如何从 kernel、allocator、connector 一直延伸到调度器。

ARGUMENT 01

GDN Prefill 的硬件专用路径

GDN 与 Full Attention 交错，使 Prefill 不再由单一 Attention kernel 代表。

Blackwell 优化 kernel 显著缩短 GDN 部分，但端到端收益还取决于其在总时间中的占比。

阅读注解

microbenchmark 的倍数不能直接外推系统速度；应使用 Amdahl 视角确认优化部分在整条 Prefill path 的权重。

每个 kernel 优化都应配一项端到端指标。

02
ARGUMENT 02

HMA 与状态 Descriptor 压缩

Hybrid Memory Allocator 将不同 layer state 映射到正确物理区域。

NIXL 只传输属于对应 layer type 的有效区域，减少 descriptors 与无效数据。

阅读注解

descriptor 数量本身也会成为 control-plane overhead；减少它既降低 handshake/launch 开销，也简化 completion tracking。

PD 性能要同时看 bytes、descriptor count 与 completion latency。

03
ARGUMENT 03

异步调度中的 Race

KV/state transfer、scheduler step 与 request lifecycle 并发推进时，错误事件顺序会产生竞态。

修复需要明确请求何时可进入 Decode batch、何时释放 P 侧状态，以及失败如何回滚。

阅读注解

把同步改成异步后，吞吐问题会转化为状态机正确性问题。每个事件都需要 idempotency 与明确 ownership。

异步优化必须附带 happens-before 关系图。

01机制

为什么减少 NIXL descriptor 数量可能在传输字节变化不大时仍提升性能？

查看提示

descriptor 也有创建、交换、提交和轮询成本。

参考推导

每个 descriptor 会带来 metadata、队列提交和 completion tracking 开销。大量小 descriptors 会增加 CPU/control-path 与 NIC work request 压力，因此合并或精确过滤可降低固定成本。

02推导

GDN kernel 快 5×，为什么端到端 Prefill 可能只快十几个百分点？

查看提示

使用 Amdahl 定律。

参考推导

只有 GDN kernel 占用的那部分时间能获得加速；其他投影、MoE、通信、调度和数据移动保持不变。若被优化部分只占总路径的一小部分，总体上限自然有限。

03设计

怎样验证 async scheduling 修复没有引入 silent corruption？

查看提示

不能只跑吞吐 benchmark。

参考推导

加入可控传输延迟/失败、请求取消、block reuse、P/D 重启和高并发随机化测试；对比 colocated 数值结果，记录 state version/ownership，并使用长时间 stress 与 sanitizer-style invariant checks。
