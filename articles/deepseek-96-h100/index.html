CORE THESIS

并行策略不应以整模型为单位选择，而应由每类算子的计算强度、状态大小和通信形态分别决定。

这是理解现代 MoE Serving 的总入口：文章第一次把 DeepSeek 风格的 DP Attention、跨节点 EP、负载均衡与 P/D 分离放进同一张端到端设计图。

01
ARGUMENT 01

为什么纯 TP 不再够用

MLA 的 latent KV 无法像普通 MHA 那样随 TP 自然切分，扩大 TP 会复制状态并压缩有效 KV 容量。

MoE 每 token 只激活少量专家，权重规模大但实际计算稀疏；继续切专家内部矩阵，容易得到效率不佳的小 GEMM。

阅读注解

这里的关键不是“TP 慢”，而是模型结构改变了 TP 的收益函数：权重切分收益还在，但 KV 复制、collective 次数和 GEMM shape 的代价开始占上风。

先按 Attention 状态、Dense FFN、Sparse FFN 三类资源分别建模。

02
ARGUMENT 02

按模块拆分并行策略

Attention 使用 DP Attention，让每个 rank 维护不同请求及其 KV；必要时再叠加较小 TP 处理低 batch。

Dense FFN 倾向 DP，Sparse FFN 则把完整专家分布到 EP ranks；LM Head 单独处理词表与峰值显存问题。

阅读注解

这已经不是传统的 TP×PP 二维网格，而是 layer-type-aware parallelism。实现上意味着调度器、通信组和模型执行路径都要理解模块边界。

“混合并行”的核心是不同层采用不同通信组，而不只是并行度相乘。

03
ARGUMENT 03

为什么 P/D 分离与 Wide-EP 相互强化

Prefill 计算密集，Decode 更依赖显存带宽与大 batch；两阶段共享同一调度循环时会互相制造抖动。

DeepEP 在 Prefill 和 Decode 使用不同优化模式，分离后可以独立选择 high-throughput 与 low-latency 通信路径。

阅读注解

PD 不只是资源池隔离，也是“执行策略隔离”。它允许两侧使用不同 batch、并行度、kernel、通信模式和扩缩容规则。

判断 PD 价值时要把可独立优化的自由度也计入收益。

04
ARGUMENT 04

EPLB 与大规模运行代价

真实请求会让专家热度偏离训练时的均匀假设，慢 rank 会把整个 EP collective 拉成长尾。

冗余专家和动态映射缓解热点，但会引入额外权重、副本管理与重排成本。

阅读注解

Wide-EP 把吞吐问题变成分布式尾延迟问题。平均 expert load 不够，应该观察每层、每 rank 的 token count 分布和等待时间。

EP 的主要可观测指标应包含负载偏斜和 A2A 暴露时间。

01机制

为什么 MLA 会削弱继续扩大 TP 的 KV 容量收益？

查看提示

分别看权重和 latent KV 是否能按 head 维度切分。

参考推导

TP 能切权重，但 MLA 的低秩 latent KV 并不具备足够的 KV heads 供各 rank 独立持有，常导致每个 TP rank 保存重复状态。TP 越大，权重占用下降，但重复 KV 和 collective 代价不会同比下降。

02推导

给定同样 32 张 GPU，什么情况下 EP16 可能优于 EP32？

查看提示

考虑 batch、节点边界、NVLink 命中比例与 A2A。

参考推导

当 batch 尚不足以摊薄通信、EP32 跨越更多节点，或更多流量落到慢速网络时，新增 ranks 带来的显存与批量收益可能小于 A2A 延迟、同步长尾和小 GEMM 效率损失。
